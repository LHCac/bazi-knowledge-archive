# 外部批命比對與跨系統互證模式

## 資料定位

本篇建立「拿到老師批命、付費命書、網路論命、其他命理系統結果後，要怎麼與本資料庫比對」的固定流程。

核心目標不是找誰比較準，而是：

```text
保留可驗證的方法。
淘汰過度武斷的固定斷語。
吸收更好的現實轉譯方式。
不同系統分開計算，再看交集。
```

---

# 一、外部批命不是權威答案，而是「待校驗來源」

任何外部批命先分四層：

```text
A. 結構事實：四柱、藏干、十神、刑沖合害、節氣、大運流年。
B. 方法判斷：身強弱、格局、喜用、成破、制化。
C. 事件翻譯：工作、感情、財務、家庭會怎麼表現。
D. 其他系統：紫微、奇門、占星、神煞等。
```

處理順序：

```text
先驗 A。
再用資料庫規則審 B。
C 保留為假說並用現實驗證。
D 獨立保存，不回灌成八字硬規則。
```

---

# 二、固定比對表

每次收到外部命理資料，至少做：

| 項目 | 外部說法 | 本資料庫 | 判定 |
|---|---|---|---|
| 排盤 | 是否一致 | 固定四柱／節氣 | 一致／需查證 |
| 日主強弱 | 外部結論 | 月令＋得生助根＋洩耗剋 | 接受／待覆核／不採 |
| 格局 | 外部格局 | 月令核心＋成破救應 | 成立／候選／不採 |
| 喜用 | 外部喜忌 | 格神、相神、扶抑、調候、行運分層 | 分層吸收／不採 |
| 刑沖合會 | 外部解讀 | 是否完整、是否化、力量比較 | 接受／降權 |
| 應事 | 外部事件 | 是否有結構＋時間層＋現實條件 | 高／中／低信度 |

---

# 三、最值得吸收的「現實轉譯」方法

分析時內部可以寫：

```text
庚食神
丁正印
卯正官
申亥害
寅申沖
```

輸出不能停在這裡。

建議固定轉成：

```text
命理結構
→ 代表哪種功能
→ 目前哪一層被引動
→ 可能出現哪些可觀察現象
→ 可以做什麼調整
```

例如：

```text
印＋食傷
→ 學習／專業與輸出
→ 大運同時強調
→ 容易一直學但成果不足，或開始把所學做成作品
→ 設定交付物、作品、考核或實作期限
```

這種「可操作化」可以正式吸收。

# 四、事件族群模型

刑沖合害不直接指定單一事件。

例如：

```text
日支被沖
```

先定位：

```text
自己／配偶宮／親密生活安排被引動
```

再列事件族群：

```text
關係靠近或疏遠
重新談界線
共同生活變更
行程與相處方式改變
重要合作關係調整
```

最後依現況縮小，不直接寫「一定分手」。

---

# 五、條件式標籤制度

以下名詞一律分級：

```text
官殺混雜
傷官見官
財星破印
官印相生
食神制殺
從格
合化
三合／三會化局
```

統一使用：

```text
候選 → 作用增強 → 部分成立 → 成立 → 有病／有救 → 破格
```

不能因兩個十神「同時出現」就跳到成立。

---

# 六、跨系統互證

若來源同時有八字、紫微等：

```text
先做八字結論。
再做紫微結論。
最後才找交集。
```

交集可寫：

> 兩套系統都把「工作成果／合作分工」列為近期高優先題目，因此值得提高觀察權重。

但不能寫：

> 因為紫微某宮化忌，所以八字某十神一定為忌。

不同系統不能互相偷換公式。

---

# 七、跨系統重疊的信度

建議分級：

```text
高：八字本身已有清楚結構，外部系統只是重複指向。
中：八字有弱訊號，另一系統也指向相同領域。
低：只有外部系統有說法，八字無明顯支持。
```

跨系統重疊只提高「值得觀察」的優先度，不提高為必然事件。

---

# 八、外部報告中的好文字，不等於好規則

外部批命常會有很準、很好懂的句子。

處理時要問：

```text
這句話背後有哪個結構？
能不能換一張命盤仍然成立？
如果不能，它是不是只是一個個案敘事？
```

只有可泛化的方法才進核心資料庫。

個人化敘事則進：

```text
08_case_archive/
```

來源與校驗則進：

```text
99_sources/
```

# 九、實際事件回饋的使用方法

當使用者回報：

```text
某天車損
某月轉職
某年分手
某時考試通過
```

可以回測當時：

```text
原局
→ 大運
→ 流年
→ 流月
→ 必要時流日
```

但只做：

```text
案例校準
事件族群修正
時間窗口驗證
```

不建立：

```text
某組干支 = 一定車禍
某個沖 = 一定分手
某個財星 = 一定發財
```

---

# 十、健康、事故與法律的限制

外部報告若寫：

```text
某宮 = 某器官一定有病
某刑沖 = 一定車禍
某官殺 = 一定有官司
```

不可直接匯入。

統一改成：

```text
命理：只作風險象意與時間提醒。
現實：醫療、交通安全、法律專業優先。
```

---

# 十一、標準輸出格式

之後比對外部批命時，可直接使用：

```text
一、外部報告說了什麼
二、與我們一致的部分
三、比我們更好的表達／方法
四、需要降權或修正的地方
五、不能匯入的內容
六、對目前個案有什麼新提醒
七、GitHub 要更新哪些規則／案例
```

# 十二、本篇速記

```text
外部批命是來源，不是權威。
結構事實先驗，格局喜用再審，事件翻譯最後驗證。
學方法，不照抄固定斷語。
事件看族群，不鎖死唯一結果。
條件式名詞先標候選。
八字、紫微分開算，再看交集。
跨系統重疊提高觀察權重，不代表必然。
實際事件可以回測，但不能反推成萬用公式。
```
